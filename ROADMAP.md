# HeiCRM Roadmap

Дорожная карта развития системы управления заявками для общежитий и кампусов.

**Дипломный проект**

**Срок реализации MVP:** до 31 января 2026 года (2 месяца)

## Краткая сводка

**Цель:** Создать полнофункциональную backend-систему из 5 микросервисов для управления заявками в общежитиях.

**Ключевые вехи:**
- **22-30 ноября** — Завершение Auth Service
- **1-15 декабря** — User Service
- **16-25 декабря** — Building Service
- **26 дек - 15 янв** — Task Service (ядро системы)
- **16-31 января** — Notification Service

**После MVP (февраль 2026+):** Analytics, Frontend, Advanced Features

## Легенда

- ✅ **Completed** — Реализовано и протестировано
- 🚧 **In Progress** — В процессе разработки
- 📋 **Planned** — Запланировано
- 💡 **Future** — Долгосрочные планы (после января 2026)

## Фаза 0: Фундамент (✅ Завершена)

### Инфраструктура
- ✅ Настройка Go Workspaces
- ✅ Структура монорепозитория
- ✅ Docker Compose для локальной разработки
- ✅ PostgreSQL подключение и пулинг
- ✅ NATS integration для межсервисной коммуникации
- ✅ Система миграций (goose)
- ✅ Логирование (файловая система)

### Общие пакеты (pkg/)
- ✅ `config` — загрузка конфигурации из YAML
- ✅ `dbx` — менеджер подключений к базе данных
- ✅ `jwt` — генерация и верификация токенов (HS512)
- ✅ `password` — хеширование паролей (bcrypt)
- ✅ `logx` — файловое логирование

### Auth Service (MVP)
- ✅ Базовая структура сервиса
- ✅ HTTP сервер на Gin
- ✅ Endpoints для login/register
- ✅ JWT токены (access + refresh)
- ✅ Middleware для авторизации
- ✅ Таблица users в БД

**Завершено:** Ноябрь 2025

**Срок:** 22-30 ноября 2025 (9 дней)

- 🚧 **Полная реализация login** — проверка пароля из БД, валидация учетных данных

## Фаза 2: User Service (📋 Запланировано)

**Срок:** 1-15 декабря 2025 (2 недели)

### Функционал (приоритетный)
- 📋 Базовые CRUD операции для пользователей
- 📋 Профили пользователей (first_name, last_name, phone, student_id)
- 📋 Просмотр и редактирование своего профиля (`GET/PUT /users/me`)
- 📋 Привязка студента к комнате в общежитии

### База данных
- 📋 Таблица `user_profiles` (first_name, last_name, phone, room_id, student_id)
- 📋 Миграции для профилей пользователей

### API Endpoints
- 📋 `GET /users` — список пользователей (admin, staff)
- 📋 `GET /users/:id` — информация о пользователе
- 📋 `PUT /users/:id` — обновление пользователя (admin)
- 📋 `GET /users/me` — текущий пользователь
- 📋 `PUT /users/me` — обновление своего профиля

### Интеграция
- 📋 Подписка на события Auth Service через NATS
- 📋 Публикация событий: `user.profile_updated`

### Тестирование
- 📋 Unit-тесты для handlers (>70% покрытие)
- 📋 Integration тесты для User API

**Результат:** Базовое управление пользователями и профилями

---

## Фаза 3: Building Service (📋 Запланировано)

**Срок:** 16-25 декабря 2025 (10 дней)

### Функционал (MVP)
- 📋 Базовое управление зданиями
- 📋 Иерархия: Здание → Этаж → Комната
- 📋 Информация о комнатах (номер, вместимость, статус)
- 📋 Привязка студентов к комнатам

### База данных
- 📋 Таблица `buildings` (name, address, floors_count)
- 📋 Таблица `floors` (building_id, floor_number)
- 📋 Таблица `rooms` (floor_id, room_number, capacity, status)
- 📋 Таблица `room_assignments` (room_id, user_id, check_in_date, is_active)

### API Endpoints
- 📋 `GET /buildings` — список общежитий
- 📋 `POST /buildings` — создание здания (admin)
- 📋 `GET /buildings/:id` — информация о здании
- 📋 `GET /rooms` — список комнат с фильтрами
- 📋 `GET /rooms/:id` — информация о комнате
- 📋 `POST /rooms/:id/assign` — заселить студента (admin, staff)

### Интеграция
- 📋 Связь с User Service через NATS
- 📋 События: `room.assigned`, `room.unassigned`

### Тестирование
- 📋 Unit-тесты для handlers (>70% покрытие)

**Результат:** Базовая система управления зданиями и комнатами

---

## Фаза 4: Task Service — Система заявок (📋 Запланировано)

**Срок:** 26 декабря 2025 - 15 января 2026 (3 недели)

### Функционал (MVP)
- 📋 Создание заявок студентами
- 📋 Предустановленные категории: Ремонт, Уборка, Доставка, IT-поддержка, Прочее
- 📋 Статусы: new, in_progress, completed, rejected
- 📋 Приоритеты: low, medium, high, critical
- 📋 Назначение исполнителя
- 📋 Комментарии к заявке
- 📋 История изменений статуса

### База данных
- 📋 Таблица `task_categories` (с предустановленными категориями)
- 📋 Таблица `tasks` (title, description, category_id, status, priority, creator_id, assignee_id, room_id)
- 📋 Таблица `task_comments` (task_id, user_id, comment)
- 📋 Таблица `task_status_history` (task_id, old_status, new_status, changed_by)

### API Endpoints для студентов
- 📋 `POST /tasks` — создать заявку
- 📋 `GET /tasks` — список своих заявок
- 📋 `GET /tasks/:id` — детали заявки
- 📋 `POST /tasks/:id/comments` — добавить комментарий

### API Endpoints для персонала
- 📋 `GET /tasks` — список всех заявок (с фильтрами)
- 📋 `PUT /tasks/:id/assign` — назначить себе заявку
- 📋 `PUT /tasks/:id/status` — изменить статус
- 📋 `GET /tasks/assigned-to-me` — мои заявки
- 📋 `GET /tasks/statistics` — базовая статистика

### API Endpoints для администраторов
- 📋 `PUT /tasks/:id/assignee` — назначить исполнителя
- 📋 `DELETE /tasks/:id` — удалить заявку

### Интеграция
- 📋 События через NATS: `task.created`, `task.assigned`, `task.status_changed`, `task.completed`

### Тестирование
- 📋 Unit-тесты для handlers (>70% покрытие)
- 📋 Integration тесты для Task API

**Результат:** Полнофункциональная система заявок (ядро проекта)

---

## Фаза 5: Notification Service (📋 Запланировано)

**Срок:** 16-31 января 2026 (2 недели)

### Функционал (MVP)
- 📋 In-app уведомления
- 📋 Email уведомления (SMTP) - базовые
- 📋 Простые шаблоны сообщений

### Типы уведомлений (приоритетные)
- 📋 Новая заявка создана (для staff)
- 📋 Заявка назначена (для исполнителя)
- 📋 Статус заявки изменен (для создателя)
- 📋 Заявка выполнена (для создателя)
- 📋 Новый комментарий к заявке

### База данных
- 📋 Таблица `notifications` (user_id, type, title, message, is_read, created_at)
- 📋 Таблица `notification_templates` (name, type, body_template)

### API Endpoints
- 📋 `GET /notifications` — список уведомлений
- 📋 `GET /notifications/unread` — непрочитанные
- 📋 `PUT /notifications/:id/read` — отметить как прочитанное
- 📋 `PUT /notifications/read-all` — отметить все

### Интеграция
- 📋 Подписка на события Task Service через NATS
- 📋 Отправка email через SMTP

### Тестирование
- 📋 Unit-тесты для handlers (>70% покрытие)
- 📋 Integration тесты для Notification API

**Результат:** Базовая система уведомлений для информирования пользователей

# Будущие планы (после января 2026)

## 💡 Analytics & Reporting Service

**Приоритет:** Средний
**Примерный срок:** Q1-Q2 2026

### Функционал
- Дашборд для администраторов с метриками

- **Для персонала:** список всех заявок, канбан-доска, назначение и обновление статусов
- **Для администраторов:** управление пользователями, зданиями, категориями заявок
